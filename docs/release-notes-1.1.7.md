# AgentDock 1.1.7 候选版本说明

　　本版代码集中修复活动中心分页、输出显示与上下文绑定，并补充恢复事务、取消、OAuth 注册容量和活动持久化容量控制。候选构建与正式发布分开进行。验收结果以对应构建的源码 SHA、测试记录和 `verification-scope.json` 为准。

## 1. 活动中心

　　项目标题移除“对话”徽标，左侧搜索框改为“搜索对话”。工具调用保留原工具标识，动作说明采用确定性的中文映射，已有具体中文标签继续显示。子调用页签及其专用加载入口删除，内部执行归属和诊断记录保留。

　　文件修改统计在简洁与详细模式中都位于时间字段之前。新增和删除继续使用已有颜色，并保留正负号与未知、预演、部分修改的区分。输出位置明确标为字节范围或保存状态，末页不再等同于全文同时可见。

　　项目更多按钮共用独立的异步分页操作，避免构造无关联路由事件的参数。进行中重复操作、失败回退、导航切换和关闭窗口分别处理，旧响应不能覆盖新的导航状态。

## 2. 工具输出设置

| 设置 | 规则 |
| --- | --- |
| 截断工具输出 | 默认开启 |
| 输出上限 | 默认 20,000，允许 1,000–100,000 范围内的整数 |
| 字符口径 | Unicode 标量值，组合标记逐码点计数，CRLF 计两个 |
| 生效时点 | 后续调用使用新快照，在途调用保留进入时设置，不重启 Core |
| 关闭开关 | 取消新增字符预算，已有采集、存储和传输上限仍然有效 |

　　stdout、stderr 等已声明普通文本字段在同一次响应中共享预算。规则文件、必需上下文、工具 Schema、控制状态和可信用户插入保留完整。图片和二进制继续使用独立限制。未知动态 MCP 结构化结果缺少可分页合同的字段保持原结构，并在 `output_policy.unapplied_fields` 中说明。

　　截断时在现有活动存储配额内保存原始普通正文，提供真实可用的 `read_file` 续读参数。`activity://call/.../source` 返回保存的文本字段 JSON，可从字节零读取并跟随 `next_offset`；无需重新运行命令。该通道检查原调用所属客户端、对话或当前任务、工作区和终止状态。正文未保存、仅保存部分、引用过期分别返回对应状态。

　　显示字符预算与续读字节偏移分开。历史记录不被改写，保存输出的下次读取按当前上限分页。普通授权命令输出保留原有环境变量优先级，活动归档继续执行更严格的环境值脱敏；归档偏移以脱敏后的保存内容为准。原工具采集计数与 `output_policy.fields` 的本次显示计数分别保留。

## 3. 上下文与注册表

　　`agentdock_context` 在读取规则前选定实际工作区，省略 `workdir` 时继承当前对话。成功返回的 `complete=true` 在所需组件及绑定协调完成后计算。`binding_updated=true` 只报告本次变更，不要求重复 bootstrap。不同目标的并发切换返回冲突，同目标可直接收敛，已运行会话和根调用历史归属保持不变。

　　注册表在跨进程锁内核验实际内容指纹，再复用解析结果和索引，避免相同版本反复反序列化。缓存失效采用 generation 隔离。权限、归属、删除和终止变化继续检查，不以单独的文件修改时间替代状态核验。

## 4. 恢复与容量

　　安装 journal 使用原子发布，备份及暂存验证成功后才切换目标。恢复失败保留原目录和仍有恢复价值的材料。备份复制有数量、深度和字节预算，普通文件保留支持的模式，链接和不支持对象明确拒绝，不把不完整备份当作成功。

　　Windows 权限转换拆出独立生命周期，只有提交成功或恢复成功并验证后才清理备份。原生状态未知时保留材料，取消不掩盖已持久化结果。权限、插入及注册表移除冗余不可取消等待，锁等待与提交前检查取消，归还本调用持有的资源。

| 容量对象 | 默认边界与处理 |
| --- | --- |
| 未完成授权的 OAuth 注册 | 独立 256 条与 256 KiB，固定一小时授权窗口，普通查询不续期 |
| 已授权客户端 | 保留原有 1,024 条及空闲生命周期，不被 pending 注册挤出 |
| 活动 Append | 默认 256 个事件及 8 MiB 序列化容量预留，覆盖排队、写入和终态预留 |

　　OAuth 容量暂不可用返回 `503 temporarily_unavailable` 与 `Retry-After`，错误参数及内部故障另行区分。活动队列无准入空间时拒绝分派；工具、后台命令和本地管理操作在产生副作用前预留终态容量。排队取消释放资源，已经提交的结果保持真实，磁盘失败仍报告审计失败。

## 5. 构建与回退

　　新增插入消息时间线：每条补充保留单独一行，显示原文预览、发送时间与真实投递状态。点击可读完整正文，右键可复制或在有效期内安全重投。消息不参与工具执行计数，不提供停止工具、重试原调用或审批按钮。

　　插入状态不再因 MCP 内层响应组装成功而直接终结。未确认消息沿用同一个消息标识，在原有效期内自动最多投递三次，人工重投计入六次总上限。新增 `insertion_ack` 接收回执，并为可集成的外层执行器提供投影后受信任附加与宿主上下文回执。接收端确认和宿主上下文确认分别显示；没有外层集成时保持未确认，避免静默显示成功。不会因此重新执行原工具。队列格式升级为版本 2，旧 `attached` 记录转为历史未确认且不自动重投；回退必须保留新队列，旧程序不能写入该格式。

　　`plugin_load` 标题改为“展开插件”，只展开成员，不改变 Heavy 设置。普通插件无需先展开才可使用已显示成员，显式展开结果同时返回实际 Heavy 属性。具体协议与回归边界见 `insertion-delivery-1.1.7.md`。

　　CI、Linux 测试、Windows 构建、资产校验及发布使用同一次解析得到的提交 SHA，并交叉核对证据。候选包默认不发布、不创建标签。安装测试只在显式启用的隔离 runner 中运行。源码检查、并发测试、WPF 编译、离屏交互、安装及人工桌面操作分别记录结果。

　　回退前先停止对应实例并保留受影响配置。新增 OAuth 生命周期字段沿用现有状态格式；旧程序不会执行新 pending 配额规则。新恢复事务尚未到达已验证终态时，不应交给旧恢复实现继续处理。历史缺少完整性记录的 journal 保留原材料，通过与其格式匹配的恢复版本处理，不绕过完整性检查。显示设置缺省可兼容，已截断且未保存的历史正文无法恢复。

　　注册表 10,000 条暖读同机中位数改善约 9.21 倍，尚未达到计划的十倍目标。原生权限异常的所有阶段、Windows ACL/owner/扩展属性和物理键盘/DPI 的完整验收，需要独立记录，不能由纯策略测试或候选包构建成功推断。
