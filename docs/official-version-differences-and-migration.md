# 扩展分支与上游官方版：差异和迁移

> English summary: this Windows-focused extension fork is not a drop-in state-format replacement for the upstream `uvwt/agentdock` release. Do not install both into the same default directories. For a cross-distribution migration, uninstall the previous package and start from a clean state, or convert only reviewed text configuration in a backup copy.

## 1. 两条发行线的关系

本仓库是基于 [`uvwt/agentdock`](https://github.com/uvwt/agentdock) 的用户扩展分支，继续保留 AgentDock 的 MCP、文件、命令、Skill、动态 MCP、浏览器和任务运行能力，但增加了面向 Windows 桌面使用、插件化开发和可观测执行的产品功能。

上游官方版与本分支可能使用相同的默认安装目录、用户状态目录、端口和启动项名称，因此它们不是可以在同一 Windows 用户下直接并装的两个独立产品。不要把一个发行线的安装包覆盖到另一个发行线的运行目录后继续使用旧状态。

## 2. 本分支的主要扩展

| 领域 | 本分支增加或强化的内容 |
| --- | --- |
| Agent 开发约定 | 自动注入用户级和工作区级 `AGENTS.md`；Skill、MCP 与插件布局尽量采用 Codex、Claude Code 等工具可直接复用的行业约定。 |
| 插件机制 | 增加插件管理、启停和权限界面；支持普通插件与 `heavy` 渐进加载插件，先暴露插件摘要，命中后再加载其中的 Skill 与 MCP 描述。 |
| 对话与任务执行 | 服务端维护对话绑定、任务线程和调用根身份；控制面板提供对话、任务、调用、审批、归档、回收站和执行详情管理。普通工具调用不要求模型反复填写对话 ID。 |
| 权限与审计 | 提供规则、只读和完全权限模式，保留显式禁止规则；记录真实工具名、状态、RPC／执行耗时、文件变更和来源，不用假成功或假零值填充旧记录。 |
| Windows 桌面 | 图形安装器、控制面板、共享浅色／深色主题、Tailscale Funnel、公网访问状态、无控制台窗口的后台启动，以及安装／升级／回滚事务。 |
| ChatGPT 展示 | 可在控制面板关闭 AgentDock 提供的 MCP Apps 内嵌界面，而不关闭工具、任务、文件或动态 MCP 能力。 |

这些扩展会引入上游不存在的状态文件、任务／执行日志、桌面设置和安装事务。即使字段名称相似，也不能假设双方能安全读取彼此所有数据。

## 3. 从上游官方版迁移到本分支

### 推荐方式：干净迁移

1. 记录当前 MCP 地址、端口和需要重新配置的外部服务，但不要复制或公开 Bearer Token、OAuth 密钥、Tunnel Token 等凭据。
2. 备份需要保留的文本资料，例如项目目录、`AGENTS.md`、自建 Skill、插件源码、MCP 配置和工作区说明。
3. 卸载上游官方版，停止其 Core、托盘、Tunnel、计划任务和启动项。
4. 将旧用户状态目录 `%USERPROFILE%\.agentdock` 重命名为只读备份，或在确认无需保留后清空。确认 `%LOCALAPPDATA%\AgentDock` 不再由旧安装占用。
5. 安装本分支，再从控制面板重新生成或填写凭据和公网访问配置。
6. 只把已检查的文本配置逐项导入，并验证插件、Skill、MCP、工作区、权限和公网访问。

### AI 辅助转换方式

需要保留大量旧文本配置时，可以让 AI 在**备份副本**中完成格式映射，再把转换结果导入全新状态目录。适合转换的对象包括：

- `AGENTS.md` 与工作区规则；
- 自建 Skill 的 Markdown、脚本和资源；
- MCP 服务器的命令、参数和非敏感环境变量名称；
- 插件清单及其 Skill／MCP 成员关系；
- 可人工复核的工作区名称和路径。

不要转换或直接复制以下运行状态：

- DPAPI 或其他机器／用户绑定的密文；
- Bearer Token、OAuth 私钥、Tunnel Token；
- 锁文件、PID、临时目录和缓存；
- 审批请求、权限版本、执行日志、调用索引和任务内部状态；
- 安装事务、版本指针、计划任务或启动项快照。

转换完成后，应先在隔离目录启动并验证，不要让 AI 直接改写唯一一份旧状态。

## 4. 从本分支迁回上游官方版

反向迁移同样应卸载本分支并使用全新上游状态。可导出的文本资料可以人工或由 AI 转换，但本分支的插件清单、`heavy` 参数、对话执行中心、审批、任务线程、显示设置与安装事务不会自动降级为上游格式。

## 5. 本分支内部升级

从本分支较早的 1.1.x 升级到 1.1.4，应使用本分支提供的 Windows 安装包。安装器通过版本化目录、试运行、健康检查和回滚事务升级，不要求手工删除正常的本分支状态。升级前仍建议保留项目和自建插件／Skill 的独立备份。

若检测到来源不明的安装目录、未完成事务、其他发行线的计划任务或无法确认所有权的启动项，先停止升级并按干净迁移处理，不要强行覆盖。

## 6. 迁移后的最小验收

完成迁移后至少确认：

1. 控制面板和 Core 版本属于同一发行线；
2. 本地健康检查通过，托盘启动没有可见控制台窗口；
3. MCP 客户端重新授权成功，工具列表和调用正常；
4. Skill、插件和动态 MCP 的来源及权限符合预期；
5. 工作区路径、任务绑定和文件写入边界正确；
6. 公网访问保留认证，并从外部网络完成一次真实验证。
