# AgentDock Workbench 1.1.7

　　本发行已按用户要求整合全部原计划查漏补缺，替换此前的1.1.7安装包；中途误标为1.1.8的修复全部归回本版。程序、桌面、安装器和发行清单内部版本均为1.1.7，保留三层权限、补充消息和全部原生验收，不仅修改发行标题。

　　从 1.1.7 开始，本分支的产品名称、软件内显示、安装器和发行标题统一使用 **AgentDock Workbench**。本版合并分层权限系统，改进任务与活动中心、用户补充投递、工具输出、上下文复用及恢复安全，并提供 Windows、Linux 和 macOS 的 x64/ARM64 安装与运行载荷。

## 2. 分层权限系统

　　合并权限 PR #13，保留原始提交 `76753cbe43cd952cdced19f6ce6c330375e34243` 的历史。权限设置分为 Permission Profile、Approval Policy 与 Approval Reviewer 三层，并继续使用现有固定请求、CallID、审批队列和原子修订检查。

| 层级 | 选项与作用 |
| --- | --- |
| Permission Profile | 文件系统 deny/read/write、网络 allow/deny、目标边界 none/workspace，限定工具准入上限 |
| Approval Policy | on-request/never/granular，决定需要审批的操作是否可以提交审批 |
| Approval Reviewer | user/auto_review，区分人工审批与管理员配置的独立审查程序 |

　　显式 Deny 和 Profile 上限优先于 Full、Allow 和审批。`never` 会拒绝原本需要审批的操作，不会自动批准。granular 要求一次操作涉及的全部类别均允许申请审批。全局与工作区设置可以继承或完整覆盖，对话 ID 不获得新的授权地位。

　　自动审查通过管理员单独部署的可信程序适配器完成。本版不内置默认模型、不让当前执行 Agent 自审、不安装审查服务或修改生产审查配置。缺配置、超时、无效 JSON、重复键、错误绑定、拒绝或取消均不派发原操作。自动批准不能变成永久工作区授权，已处理审批不重复执行。

　　这套 Profile 实现的是**工具准入限制**。它没有建立操作系统进程沙箱或系统防火墙。受限配置拒绝无法约束的任意 shell、第三方 MCP、WSL 和动态加载调用；不能用审批把它们变成隔离执行。已有后台进程不会因修改 Profile 自动停止。Windows 合并验收发现的长短路径别名问题已通过与工作区路由共用的规范化比较修复，受保护的 AgentDockHome 及其祖先目录不会因 8.3 别名差异被当作普通写入目标。

　　权限详细语义、迁移方式、独立审查器协议与限制见 `docs/permission-profiles.md`。Windows 设置窗口增加三层编辑与继承选择，审批详情展示实际审查主体。

## 3. 活动中心与补充消息

　　插入的用户补充在时间线中显示独立一条记录，包含正文预览、发送时间和真实投递状态。点击可读完整正文，右键可复制、停止后续投递或在有效期内重投。重复投递更新同一个消息标识，不增加工具计数，不提供原工具的停止、审批或重试按钮。

　　内层 MCP 响应组装成功不再直接结束投递。新增 `insertion_ack` 回执，接收端确认与宿主上下文确认分别显示。未确认补充沿用同一 ID，在原 300 秒有效期内自动最多投递三次，人工重投计入六次总上限。重投只附加消息，不重新执行原命令、文件修改或其他业务工具。

　　嵌入式外层执行器可以接入 `InvokeProjected`，在业务字段投影后附回独立保留的可信补充，再由宿主单独提交确认。私有回执令牌不交给投影脚本，也不进入活动归档或消息列表。第三方结果中的同名字段不会被提升为可信用户补充。

　　**外部宿主仍需要接入对应能力**。本版没有改写 ChatGPT 的外部 `functions.exec`。没有宿主转发/提交证据时保留“未确认收到”，实际收到内容的接收端可以提供接收回执。工具参数不能自行宣称已提交模型上下文。完整接口与默认无状态 HTTP 的降级行为见 `docs/insertion-delivery-1.1.7.md`。

　　同时修复项目“…”展开的路由事件异常、快速重复触发和分页竞争。移除左侧“对话”徽标，搜索框改为“搜索对话”；统一中文动作说明，移除无用子调用页签；简洁与详细模式都把文件新增/删除行数放在时间之前。普通插件的 `plugin_load` 文案改为“展开插件”，并返回实际 Heavy 属性，不会因为展开动作改变用户配置。

## 4. 输出、上下文与恢复

　　工具普通文本输出支持 1,000–100,000 的整数上限，默认开启、20,000 个 Unicode 标量值。同一响应内 stdout/stderr 等普通正文共享预算，规则、Schema、必要上下文、控制信息和可信补充独立保留。设置热更新不重启 Core，在途调用保留进入时快照。字符上限与保存内容的字节偏移分开，截断后只提供实际存在的续读引用，不重新执行原工具。

　　`agentdock_context` 在一次请求内确定目标工作区、加载规则并完成绑定协调。成功的 `complete=true` 与最终目标一致，`binding_updated` 不再要求重复 bootstrap。注册表复用解析结果和索引，缓存按 generation 隔离，权限、终止与外部修改的校验保留。

　　安装恢复先验证备份与暂存再切换目标，journal 原子发布，恢复失败保留原目录和有用材料。Windows 权限转换区分完成、恢复与未知阶段，未验证终态不清理备份。锁等待支持取消，OAuth 未授权注册使用独立配额，活动记录在派发副作用前预留终态容量，避免过载后静默丢失必需记录。

　　补齐 macOS 原生验收：活动输出和恢复路径允许系统自带、root 所有且目标匹配的 `/var`、`/tmp`、`/etc` 祖先别名，普通符号链接与最终链接目标仍被拒绝，别名路径的恢复重叠检查保持一致。各平台载荷附带仓库原始 Apache-2.0 许可证，Linux RPM 元数据与许可证一致。

## 5. 补齐的恢复、键盘与性能要求

　　Windows 备份、暂存和恢复逐项验证 owner、group、DACL 与支持的只读、隐藏、归档属性，安全描述符使用原生备份流恢复。ADS、EA、reparse、压缩、稀疏、加密等无法完整保真的对象在提交与替换前明确拒绝，保留源对象。文件模式与原生元数据测试分别执行。

　　计划任务的 task.xml/state.json 原子保存，恢复前核对 XML 摘要、原任务存在性和安全描述符。准备、应用、验证、取消、恢复失败、恢复后验证失败、原生进程未知、定义篡改和原任务不存在均加入 Windows x64/ARM64 原生 COM/NTFS 故障验收。任务调度器仅允许每个 ACE、重复数和组内顺序完全不变的纯 Allow 规范化；权限位、SID、保护/继承标志或其他 ACE 变化仍拒绝，恢复任务定义不自动触发 registration trigger。

　　更多按钮补齐真实 WPF 窗口上的 Enter/Space KeyEvent，经 Button 类处理器进入分页逻辑；鼠标、UIA、100轮分页、空页/删除、搜索切换、明暗主题、800/1280宽度与四档渲染DPI一并回归。这些测试不替代所有物理键盘与显示器组合。

　　注册表使用最多16 MiB的不可变编码快照，暖读在跨进程锁内逐字节比较实际文件并复用解析结果，变化、取消、权限、终止和外部写入仍检查。对应原十倍目标的三轮同机测量均已达到要求，完整 Runtime.Call(agentdock_context) 另测960个冷暖及并发请求。保留实际样本、SHA和分配量，不把注册表倍数当作外部网络或ChatGPT渲染加速倍数。

　　完整 R01–R09、F01–F11 对照见 `docs/acceptance-1.1.7.md`。产品版本改回1.1.7后仍强制执行两个Windows原生恢复作业、ARM64原生安装作业、x64安装及Linux包事务；缺少同SHA证据或任何门禁失败均不发布。

## 6. 升级与验证边界

　　现有数据目录、服务 ID、命令名称、Bundle ID 和升级资产文件名保持兼容，旧发行记录不改名。`agentdock version` 与 JSON `product_name` 使用新名称；旧 `--version` 首行作为 1.1.6 更新器的兼容探测协议保留，并增加 `product: AgentDock Workbench` 字段。

　　插入队列升级为 schema 2，历史 `attached` 记录标为未确认且不自动重发。权限文件首次编辑新设置时升级 schema 2。回退到不认识新格式的版本前，需要保留新数据并恢复适用备份，不能直接删除字段或把新队列交给旧程序继续写入。

　　本次替换先通过 GitHub Actions 六个目标的同SHA完整构建与验证，再以独立恢复发布入口替换指定发行。Windows x64与ARM64均执行原生载荷和隔离安装/修复/卸载，Linux两架构执行DEB原生安装/验证/移除和真实RPM独立根事务，macOS保持双架构原生后端及通用App验证。安装、原生恢复与资产摘要分别记录，完整新资产核对后才设为正式Latest。

　　已经安装旧1.1.7的用户应重新下载本发行安装器执行更新；版本号相同，不能仅凭版本字符串判断是否已取得全部补缺，以内嵌commit和release-manifest.json为准。误装1.1.8的用户需要手动更正版本，先保留配置与进行中的恢复材料，不强制终止生产会话或混用恢复器。

　　Windows 自有二进制与 Setup 未进行 Authenticode 发布者签名。macOS 使用 ad-hoc 签名，未使用 Apple Developer ID 公证，系统可能显示未知发布者或首次打开拦截。完整人工桌面、物理设备以及所有 Windows ACL/owner/扩展属性组合不由自动化编译结果替代。实际执行和未运行项以本发行清单中的验证记录为准。
