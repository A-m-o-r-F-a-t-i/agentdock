# AgentDock 1.1.6

　　本版集中修复上下文重复扫描与取消积压、插入消息在结构化宿主中不可见、关闭应用显示后仍声明模板，以及活动中心只显示动作名称却缺少真实参数和输出的问题。同时调整项目导航、文件编辑统计和控制面板入口，并整合用户分支与上游的独立改进。

## 1. 上下文性能与复用

　　插件目录采用不可变快照和成员索引。相同输入的冷请求共享一次构建，热调用复用完整快照，Skill 和 MCP 归属查询不再逐项重扫所有插件。Heavy 筛选提前到正文读取之前，未选择的服务不会因为获取上下文而被启动。

　　规则、Skill、插件和 MCP 目录按作用域分别失效。共享构建不混用请求身份、权限、任务绑定或用户插入。一个等待者取消不会中断其他等待者，最后等待者退出后取消无用构建，同一键未收敛前不启动第二批后台构建。

　　新增 `AGENTDOCK_CONTEXT_TIMEOUT_MS`，默认 5000 ms，只约束上下文准备链，不改变业务命令或动态 MCP 的超时。首轮加载、工作区切换、定向目录刷新和同工作区复用采用一致指引，普通错误和后台命令观察不再要求机械重载完整上下文。

　　最终性能报告与原始样本见 `docs/validation/1.1.6/context-performance.md`、`context-root-samples.json`、`mcp-catalog.md` 和 `mcp-discovery-end-to-end.json`。冷缓存指进程内缓存状态，未清除操作系统文件缓存。测量不包含 ChatGPT 公网传输、模型推理或网页渲染。

## 2. 插入消息与应用显示协议

　　活动中心插入同时进入 MCP 尾部文本块和顶层 `structuredContent.agentdock_guidance.response_additions`，共用同一个 `insertion_id`。SDK 与直接调用经过统一响应附加器，保留原业务对象、错误、图片、资源和目录摘要，并防止一次响应装配消费两次队列。

　　第三方业务结果内的同名字段保持为业务数据，不能被提升成可信插入。界面将 `attached` 表述为“已写入工具响应”，不以服务端写入状态推断模型已经收到或已读。原有三分钟插入资格和五分钟未领取失效规则保留。

　　TextOnly/App 使用同一呈现状态管理工具目录、结果元数据和资源。TextOnly 不再发布新的模板引用，曾经发布且仍在兼容窗口内的模板 URI 返回受控惰性资源。模式切换同步使目录和资源代际失效。协议回归覆盖声明过滤、旧资源、双通道插入与结果保留；当前用户正在使用的旧进程不会被本次构建自动替换。

## 3. 完整 MCP 摘要与批量 Schema

　　已知服务可直接调用 `mcp_tool_list` 获得当前可见的整套名称和一行描述。`mcp_tool_inspect` 的 `names` 支持多个精确名称、`service:*` 和多个服务混合选择，保留完整输入/输出 Schema、引用和约束。原单值请求在同一入口归一化。

　　每次 `mcp_tool_call` 响应附带该服务的完整摘要，复用同一分页目录缓存，不要求每次重新搜索或查询 Schema。业务结果、目录、插入按固定顺序装配。目录附加失败独立记录，不能把已经成功的业务操作改成失败并诱发重复写入。禁用成员、权限和 Heavy 加载边界继续生效。

## 4. 活动中心真实调用记录

　　外部根调用接受并绑定对话后即持久化请求和运行状态，通过活动流更新导航，不必等待第一次工具完成。缺少宿主标题时使用工具和动作形成可区分标题，真实标题到达后沿用已有优先级规则更新。

　　详情划分为“调用”和“输出”，保留已脱敏的真实参数、结构化结果及全部 MCP 内容块。命令和动态 MCP 进度在执行期间更新，失败、取消和超时不清空此前保存的内容。图片和二进制记录类型与引用，不向文本框灌入原始字节。

　　大结果采用有界预览和授权分段读取。当前显示字节范围、总字节数和行数，可前后翻阅并复制当前已脱敏页。未保存、旧记录缺少输出和部分结果分别标明原因，不能把动作摘要伪装成输出。内部调用保留父子关系，业务结果不会被每个内部 span 重复保存和累计。

　　列表和详情统一总耗时来源。历史 `elapsed_ms` 仍可见，缺少 RPC/执行/等待分项时保留未知，已记录的零值不会被当作缺失。

## 5. 项目导航与工具栏

　　项目默认显示最近 120 秒内有有效活动或运行时确认仍在执行的对话。没有活动时完全折叠。默认活动列表不受历史五条限制，旧任务的 `running` 标签也不会让项目永久活跃。

　　点击三角进入最近五条历史，再点省略号按 20、40、60 条继续展开。历史使用冻结排序快照，实时新增单独合并，移动的活动时间不会造成翻页重复或漏项。搜索覆盖服务端完整数据源。手动折叠和历史展开在当前窗口内保留，不被刷新覆盖。

　　省略号行高为普通对话行的一半，完全折叠时子列表和省略号不占位。增加“折叠全部项目”，同时保留右侧当前内容、插入草稿和正在执行的任务。新活动不会自动撑开已经手动收起的项目。

　　任务中心增加“控制面板”按钮，复用现有窗口和运行时。删除连接、主题和更早按钮，简洁/详细合为一个切换按钮。向上阅读调用历史时自动续页，保留原记录与滚动位置，加载失败在原位置提供重试。

## 6. 文件编辑统计

　　撤销固定 `EDIT_FILE` 标签，显示真实注册工具名。根调用最右侧显示绿色新增和红色删除行数，详情保存每个文件的动作与统计。数字来自同一次受版本保护的实际编辑事务，不根据截断的 diff 文本或当前仓库状态补算历史。

　　逻辑行口径统一处理 UTF-8、中文、空文件、CRLF/LF 和末尾无换行。纯移动为零增减，同一文件多次内部修改只比较最初状态和最终提交。覆盖移动保留被覆盖目标的实际删除统计。统一 Git diff 先在隔离镜像求值，再用原始快照保护实际落盘。

　　预演只显示拟议值，完整回滚为已知零，连接中断或归属无法确认时保留未知。部分回滚只汇总仍能确认属于本次操作的残留变化，并标记部分状态和未核实路径。Windows 按可表达的只读属性核对文件模式，WSL 使用原生权限、所有者和内容摘要保护事务。已完成写入后的清理故障与业务结果分开记录。

## 7. 控制面板与上游整合

　　显示与主题移到“运行配置”最前，原配置键继续使用，旧 `display` 路由转到新位置。删除独立显示页。分组框改为单一 2 DIP 主题描边，保持输入框和键盘焦点样式。

　　上游使用真实双父合并整合，保留用户 fork 的任务、对话、插入、停止、权限、Heavy 和 Skill 版本模型，移植不冲突的源适配器、租约、路径安全和 Windows 诊断改进。取舍与固定提交见 `docs/upstream-integration-1.1.6.md`。

## 8. Windows 安装事务修复

　　1.1.6 原安装包在 trial 阶段将安装器的 `service start`、状态查询和回滚 `service stop` 发给稳定启动器。该入口只允许持有匹配安装事务锁的服务宿主启动，普通管理命令因此被拒绝并误入自更新事务检查，报出缺少 `update/transaction.json`。此故障不以旧版正在运行为前提。

　　安装器现在复用 `ActiveCoreBinary`，每次管理操作都按当前活动指针选择实际 Core。停止试运行版本、恢复文件后重启旧版分别解析各自的代际目录，不固定使用目标版本或传入安装包。普通启动器的 trial 拒绝规则、计划任务的稳定入口、健康检查与提交/回滚顺序均保持不变，不伪造自更新事务，也不提前提交版本。

　　新增测试覆盖安装前旧版、trial 新版、回滚后旧版、提交后新版及未激活目录。Windows 回归在临时目录构建真实 Core 和启动器，核对安装器管理链可达、普通入口仍被拒绝、活动指针不变且不生成自更新事务。该测试使用模拟健康响应，不执行 Setup 或真实 Core 服务安装，不能代替用户试装。

## 9. 内置 Skill 清单与产物验证

　　修复内置 Skill Bundle 生成器遗漏 `version` 字段的问题。清单中的名称、版本、包路径和摘要与运行时 Bootstrap 契约保持一致，版本从各自 `SKILL.md` 读取；缺失、空白或无效版本会在构建阶段失败，不推迟到用户安装时处理。保留包摘要和清单身份一致性检查。

　　新增真实生成器到运行时 Bootstrap 的交叉回归，覆盖首次安装、同版本重复安装、激活结果、内置目录归属和版本缺失。Windows 产物校验进一步使用最终 ZIP 中的 Core 和 Bundle，在临时 `AGENTDOCK_HOME` 实际执行两次 Bootstrap，逐项核对结果与安装后的状态。任何一步失败均阻止候选产物交付。此检查不启动 Setup、Core 服务或计划任务，不改用户现有 Skill。

## 10. 构建、验证与安装边界

　　原 `v1.1.6` Release 已撤回为草稿，公开 Latest 恢复为 `v1.1.5`。修复包由用户 fork 的 GitHub Actions 以 `publish=false`、`installation_tests=false` 构建为 `candidate-not-released`；用户试装确认前不得重新发布或移动版本 tag。Windows Go 回归、静态分析、桌面纯逻辑、离屏 WPF 布局、安装脚本静态契约，以及 Linux/WSL 事务与并发检测分别记录结果。离屏样本不等同于真实显示器 DPI 切换或人工键盘验收。

　　Windows CI 采用 `go test -p 1` 隔离不同包的资源占用，避免真实二进制构建与其他包的进程、文件记录测试同时争用运行器。仍执行全部包，保留用例内部并发、原有截止时间及全部断言；Linux 全量回归和 race 检测不变。

　　普通候选和 tag 构建不启动安装器。没有在用户电脑启动新版界面、安装、覆盖当前进程或执行故障注入。安装/升级/回滚、当前 ChatGPT 真实宿主与新版二进制连用的端到端验收，以及实际模型调用次数评估，均不得由自动化协议测试代替。最终验收状态、原始样本与构建记录以本版验证目录和对应 Actions run 为准。

　　逐项追踪矩阵见 `docs/releases/v1.1.6-acceptance.json`。当前可核实的旧版计划包含 A/U/F/P/M/G 共 94 项；历史材料提到新版计划另有 A19–A25、U13–U23、M15–M28 共 32 项，但本轮未取得这些条目的逐项原文，因此矩阵将其保留为 `source_missing`，不根据范围摘要补写原要求。

　　历史候选 GitHub Actions 35980716534（提交 e4ea5c4）的记录不包含本次安装修复，不能作为修复包验收。修复包的完整回归、构建提交、校验与执行范围以新的候选 Actions run 及其 `verification-scope.json` 为准。实际模型额外调用次数、真实 ChatGPT 宿主端到端、真实窗口键盘/DPI 和安装/卸载验收未执行，不计为全项通过。
