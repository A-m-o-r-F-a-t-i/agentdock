# AgentDock 1.0.0

　　本次发布修复 Windows 覆盖安装、升级试运行和回滚启动中的问题，并汇总本分支的插件管理、Heavy 渐进加载、运行配置页面与安装目录选择改进。面向 Windows x64 提供离线安装包，应用名称统一为 **AgentDock**。

　　本 Release 发布于 `A-m-o-r-F-a-t-i/agentdock`，基于 `uvwt/agentdock` 开发。本分支的核心更新检查和安装脚本下载入口已指向本仓库，避免后续更新切换回上游发行版。

## 1. Windows 安装与升级修复

| 修复项 | 原有影响 | 本版处理 |
| --- | --- | --- |
| 原生 Task Scheduler COM 参数布局 | 64 位系统调用 `RunEx` 时可能返回 `0x80020005`，安装启动与回滚启动均受影响 | 修正 `VARIANT` 的完整本机布局，补充 ABI 和真实多参数 COM 调用回归 |
| 升级期间调用错误的启动入口 | 稳定入口拒绝尚未提交的安装版本，或回滚再次调用旧核心中的故障实现 | 安装适配器统一使用已校验的新载荷核心执行启动桥接，目标实例仍由安装清单决定 |
| Setup 升级试运行的进程环境 | 核心及 Tunnel 从安装器进程树启动，与正常登录启动的环境不一致 | 通过当前用户会话启动升级 Engine，继续执行同一套试运行、健康检查和提交事务 |
| 启动成功判断不完整 | 依赖计划任务时间戳，尚未确认目标进程创建便作出判断 | 使用本次启动专属的子进程回执，补充原生错误、标准输出和错误输出，失败时清理临时任务 |
| 安装试运行与稳定入口的配合 | 提权核心任务需要通过稳定入口启动，但该入口不能随意放行未完成安装 | 仅为 `service launch-core` 校验匹配的安装事务、目标版本、目录、阶段及仍被持有的事务锁，其余入口继续拒绝未提交版本 |

　　升级中的托盘直接使用当前试运行版本，完成外部状态配置后再提交安装事务。失败回滚保留原版本、受保护凭据和用户数据，回滚完成后允许重新安装。安装器的 Skill 自举继续隔离无关的旧运行参数，避免残留的指令文件、ACP 或浏览器配置阻断安装。

## 2. 插件与控制面板

- **插件管理**：插件卡片支持收起、展开、总开关、成员开关和 Heavy 切换。插件成员不再重复出现在独立 Skill/MCP 列表中。普通插件直接披露已启用成员，Heavy 插件先提供摘要，调用 `plugin_load` 后再展开。
- **插件目录**：插件根目录使用 `plugin.json`、`mcp.json` 和 `skills/`，包内容与宿主开关、本机配置、凭据引用及持久数据分离。旧私有格式的迁移纳入安装事务，失败时可恢复。
- **运行配置**：新增页面集中配置默认全局工作区、AGENTS.md 自动加载、额外指令文件、浏览器程序、可信代理范围、命令环境变量引用以及 ACP 并发数和交互超时。数据及配置路径只读展示，保存前校验。

　　“功能与插件”页面已移除插件包“安装”和“更新”按钮及对应 GUI 流程，保留已安装能力的管理和 Core 更新入口。全局与工作区 AGENTS.md 自动加载能力继续保留。

## 3. 安装方式与目录规则

1. 下载附件 **`AgentDockSetup-amd64.exe`**。从 0.8.3 或本分支的旧插件版本升级时，使用本次完整安装包，选择已有安装目录。旧版 Core 自更新入口不负责本次私有插件格式迁移。
2. 全新安装可以选择目录。已有有效安装时继续使用原位置，避免两份程序争用启动项和端口。需要更换位置时，先卸载并保留用户数据，再安装到新目录。
3. 安装位置与 `.agentdock` 用户数据目录独立，覆盖安装不要求删除用户数据。部署前应保存重要配置与插件数据的备份。

　　旧安装已经留下 `external_rollback_failed` 时，本版仍要求先恢复对应任务、注册表或服务状态，再结束该失败事务。安装器不会仅通过删除错误标记来宣称恢复成功。此前已经完成保留数据卸载、重装且恢复正常的实例，可按普通覆盖升级处理。

| 官方 0.8.3 历史安装器与载荷 → 1.0.0 | 升级、故障注入回滚、回滚后重试及同版本覆盖通过 |
| 0.8.4-agent-plugins.1 → 1.0.0 | 升级、故障注入回滚、回滚后重试及同版本覆盖通过 |

| 残留旧运行参数的新装 | 注入已删除的指令/浏览器路径及非法旧 ACP 参数后安装、启动与覆盖通过 |
| 新装时模拟启动桥接失败 | 保留安装与启动项，明确返回延后启动告警，通过 |
| 原生启动桥接 | 非零退出诊断、UTF-8 JSON、连续快速启动及临时资源清理通过 |
| Go 测试与静态检查 | 50 个包通过，1,422 项测试（含子测试）通过，71 项按环境条件跳过；`go vet ./...` 通过 |

　　真实安装回归在当前 Windows x64 主机使用独立的安装目录、数据目录、端口和启动项进行，目录包含中文及空格。回归包含实际 Core 启动、精确版本健康检查、凭据文件哈希和数据哨兵核验。故障注入发生在 Engine 完成试运行之后、安装提交之前，并检查旧实例恢复及再次安装结果。

## 5. 发布范围与附件

| 附件 | 用途 |
| --- | --- |
| `AgentDockSetup-amd64.exe` | Windows x64 离线安装、覆盖升级与修复 |
| `agentdock_windows_amd64.zip` | 同一版本的 Windows x64 完整载荷 |
| 对应 `.sha256` 与 `SHA256SUMS.txt` | 核对下载完整性 |
| `verification-report.json` | 本次构建与测试范围、结果及产物哈希 |

　　此安装包未配置 Authenticode 发布者签名，Windows 可能显示未知发布者提示。随包 cloudflared 使用已核验签名的现有发行二进制。SHA-256 用于完整性核对，不替代发布者签名。

　　本轮发布仅提供 Windows x64 成品。真实升级回归覆盖标准权限、本机访问模式及 Setup 调用的安装脚本，不包含独立新 Windows 用户、管理员 UAC、真实公网 Tunnel 或 ARM64 设备的完整安装验证。安装包构建与向导检查不等同于上述未执行的场景。

## 6. 开发与复核

　　安装升级回归入口为 `scripts/test/test-windows-upgrade-isolated.ps1`，支持指定历史安装器和载荷建立真实旧版安装状态。启动桥接回归入口为 `scripts/test/test-windows-runtime-launch-diagnostics.ps1`，覆盖成功、非零退出、UTF-8 JSON、快速连续启动及临时资源清理。新增测试已纳入脚本治理清单。
