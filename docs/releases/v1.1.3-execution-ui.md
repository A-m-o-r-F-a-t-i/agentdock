# AgentDock 1.1.3：对话执行界面与管理

　　本次以已发布的 v1.1.2（fce9104）为基础实施，交付独立开发分支、Windows amd64 本地候选构建和验收记录。未覆盖运行中的实例，未推送 GitHub 或创建正式 Release。

## 1. 界面调整

　　导航层级统一为“工作区 → 对话 → 对话内任务与执行记录”。侧栏保留工作区折叠、名称和数量，对话默认只显示名称，更多操作在悬停、选中或键盘聚焦时出现。普通状态圆点、方块和文件夹装饰已删除。

　　主区只有一条对话标题行，权限、连接、主题、设置、待处理和当前对话操作合并在该行。独立“执行中心”标题、空白顶栏和重复工作区副标题已移除。任务进度使用紧凑下拉、步骤数、进度条和当前步骤，下一动作与验收条件进入任务详情。

　　调用使用 36 DIP 单行，显示状态、动作名和耗时，窄窗口隐藏时间。调用、任务和帮助共用下方详情区。调用详情按“命令与输出、来源、子调用、技术”组织，失败、待审批和未知结果不自动撑开列表。

　　浅色、深色和跟随系统使用相同布局，主题覆盖侧栏文字、选择背景、菜单、输入控件和滚动条。搜索、分组折叠、滚动位置和显示偏好均保留。历史任务和未归属记录通过独立管理面板处理，不加入对话侧栏成为并列导航。

## 2. 执行与数据管理

| 功能 | 实现规则 |
| --- | --- |
| 终止对话 | 本地用户确认后，先持久化终止门禁，再拒绝待审批请求并停止该对话的运行调用，包括异步命令。门禁与执行准入共用锁。 |
| 后续请求 | 返回 `CONVERSATION_TERMINATED`，消息为“用户已终止此对话，请停止执行。”。普通工具调用不能自行解除门禁。 |
| 本地恢复 | 仅允许本地管理入口确认恢复，不重放已取消的请求。历史读取、导出及管理不受终止门禁阻断。 |
| 对话名称 | 手动名称、宿主标题、首个明确任务、操作名称、工作区与创建时间依次降级。旧自定义名称保持不变。 |
| 来源 | 区分读取中、已解析、暂不可用、已删除和读取失败。已删除来源使用 HTTP 410，与暂不可用的 404 分开。 |
| 旧任务 | 保留原任务 ID。缺失步骤显示“进度未记录”，缺失分支信息不阻断调用列表。 |
| 调用管理 | 原始调用 ID 和旧日志投影的稳定 ID 均可导出、隔离、归档、移入回收站和永久删除。运行中及待审批调用拒绝删除。 |
| 删除持久化 | 调用删除使用独立管理覆盖层和持久化删除标记，日志重放、重新打开存储及迟到子调用不会重新显示已删除调用。对话删除保留来源墓碑，避免同一来源重新生成对话。 |
| 批量操作 | 使用明确 ID 快照，每批至多 200 项。用户重新选择对象时作废原有全选快照，防止旧批量范围影响后续操作。 |

　　对话、任务管理对象与执行审计记录采用独立保留规则。删除对话或任务不连带删除工作区文件，独立保留的调用可在记录管理中进一步删除。调用永久删除隐藏查询与重放结果，原始审计日志仍按日志保留策略处理，不执行磁盘安全擦除。

## 3. 权限与连接

　　权限入口展示对话、工作区和全局继承关系。完全权限沿用服务端现有的全局／工作区范围限制，对话层可单独收紧权限。权限编辑保留版本检查，显式禁止规则不被完全权限覆盖。

　　客户端状态来自实际通过认证的 MCP 请求，分别展示已连接、最近已连接、已授权、需要重新授权和本次启动尚无记录。匿名发现和陌生无效请求不会把已确认连接降级为需要授权。公网可达性单独检查，检测结果不改写客户端授权证据。状态接口不返回凭据或内部凭据摘要。

　　宿主可以通过可选的 `agentdock/conversation-title` 元数据提供标题，这是 AgentDock 的可选扩展。普通工具参数无需逐次填写对话 ID，原有服务端上下文继承机制保持不变。

| 构建环境 | Windows amd64、Go 1.26.5、.NET SDK 8.0.425。 |

| 新增专项 | 18 项覆盖名称优先级、终止与恢复、重启、异步命令隔离、审批竞态、连接证据、稳定记录 ID、删除重放、真实 HTTP/MCP 管理链路，以及批量命名、取消和并发名称保护。 |

| Windows 界面 | 实际 WPF 窗口配合隔离 HTTP 夹具；编译 0 警告、0 错误，交互、分页、分支浏览及关闭窗口不停止任务等回归通过。 |

| 主题及缩放 | 浅色、深色、跟随系统，以及 100%、125%、150%、200% WPF 渲染目标检查。 |

　　首次实现结果保存在 `v1.1.3-implementation-verification.json`，补充验收使用 `v1.1.3-upgrade-verification.json`。前端大列表数据用于检验分页和窗口行为，不代表真实生产日志冷查询性能。缩放截图未通过切换物理显示器 DPI 获取。截图中的任务名称和记录来自隔离测试样本。

　　补充实测发现旧占位对话的首次命名逐条读写整份注册表。已改成复用快照、缓存共享任务名称、单次受锁保护的批量提交，并在取消后停止扫描与写入。Windows amd64、1,000 个合成旧对话、首屏 200 项的真实 Core HTTP 请求，从原候选的 15,911.86 ms 降为修复后交付核心的 29.63 ms。这是本轮首次请求的单次测量，包含名称迁移，不是生产环境长期延迟统计。

## 5. 构建与交付边界

```powershell
# 在已安装 Go、.NET 8 SDK 和 Inno Setup 6 的 Windows 环境中执行。
# 此脚本同时生成可分发压缩包与离线安装包，不执行安装。
.\packaging\windows\build-windows-release.ps1 `
  -Architectures amd64 `
  -OutputDirectory <候选构建目录> `
  -CloudflaredBinary <签名有效的cloudflared.exe路径> `
  -Candidate
```

　　最新候选由干净提交 `22adcb769cefe018a0291cfc2bfaf15ff8c600a1` 构建，版本仍为 1.1.3。随后补交的验收文档不改变已测试的二进制。安装包没有 Authenticode 签名，当前只交付 Windows amd64；运行中的 1.1.2、生产启动项和版本指针未改变，没有向远端仓库推送分支、标签或创建正式 Release。

## 6. 安装、升级与真实数据补充验收

　　原生 Inno 验收使用与交付包相同的 Core、GUI 和辅助程序载荷，仅对测试安装器的 AppId、启动项名称、快捷方式及安装目录回退位置做隔离。测试目录包含中文与空格。最终载荷的压缩包摘要记录在补充验收 JSON 中，原始项目文件、Skill、插件、MCP 伴随数据及工作区规则均完成保留检查。

| 场景 | 验证结果 |
| --- | --- |
| 1.1.2 → 1.1.3 升级 | 健康检查与版本检查通过，安装事务提交成功。 |
| 升级提交前故障 | 在试运行成功、提交前注入错误，安装器按预期返回 7，并恢复旧核心、版本指针、凭据和用户数据。 |
| 同版本覆盖修复及失败回滚 | 成功路径提交，同版本故障路径保留原始程序字节和数据。 |
| 卸载与保留数据重装 | 卸载后项目文件与用户数据保留，重装后健康检查通过。 |
| 空目录全新安装 | 在空安装目录和空 AgentDock 用户数据目录完成安装、版本检查及卸载；未创建新的 Windows 用户账户。 |
| 黑框检查 | 窗口事件观察器自检通过；9 次被观察的安装／卸载流程均未出现新的可见控制台窗口。 |
| 生产状态保护 | 生产启动项和版本指针前后相同，测试进程按独立目录清理。 |

　　另以实际 1.1.2 核心创建任务、执行记录、手动名称和待审批请求，再由交付的 1.1.3 核心读取同一份隔离数据。四次进程启动覆盖升级及后续重启：标识、手动名称和执行历史保留，旧待审批写入没有自动执行；实际异步命令能够被终止，另一对话保持可用；终止门禁、调用删除标记与对话删除标记跨重启有效，本地恢复不重放已取消请求。

　　上述安装结果对应隔离 AppId 的原生安装器和本机普通用户环境，不等同于对当前生产实例执行覆盖安装。没有测试管理员安装、ARM64 设备或系统断电场景。性能、二进制、原生安装器和界面结果分别保留，避免把合成数据的速度或窗口截图当作生产日志性能结论。
