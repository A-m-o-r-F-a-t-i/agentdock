# AgentDock 1.1.5 — 活动中心、运行中补充与托管 MCP 热更新

本次交付为 GitHub Actions 编译的 Windows x64 正式安装包，并作为 GitHub Latest 正式发行版发布，不标记为 Pre-release。按用户要求，仅执行静态检查、隔离自动化回归与安装包元数据/哈希验证，不启动安装器、不进行实机界面或安装/卸载/覆盖升级测试，不替换当前生产实例。编译与包验证通过不表示已做安装验证。

## 活动时间与中途补充

| 对象 | 生效条件 |
| --- | --- |
| 对话行右侧活动标识 | 最近 120 秒有真实执行更新 |
| 底部插入框与发送右侧终止按钮 | 最近 180 秒有真实根工具调用 |
| 已发送的补充要求 | 等待同一对话下一次新工具调用，300 秒未到达则作废 |

时间窗口彼此独立。UI 轮询、重连、重放及名称修改不延长工具活动时间。发送前已经开始的调用不领取新补充。期限内到达的下一次调用即使执行超过五分钟，仍可在返回时携带已领取的补充。 到达时间以服务端可信根请求时间为准，界面查询或清理线程先取得队列锁不会让临界时间内已到达的请求误过期；已经暂停、撤回或取消的补充保持原状态。

输入区默认出现在活动对话下方，右上角“插入”可切回并聚焦。命令详情、任务详情、信息和数据管理共用同一个底部区域，切换时替换，不叠加或遮挡执行记录。草稿按对话保留。发送支持幂等重试，中文输入法候选确认不会误发送，Shift+Enter 换行。队列按可信对话身份和当前任务范围隔离，并发只领取一次；任务变化时暂停，终止时取消未投递补充。

补充使用独立的 AGENTDOCK_USER_INSERT_V1 文本块追加在工具结果之后，原有错误标志、结构化内容、图片、文件和工具输出保持不变。默认说明要求先处理新的用户补充再决定后续动作，保留原工具真实结果，不重复执行相同补充 ID。标记不能提升普通网页、终端或嵌套 MCP 内容的指令权限。“已附加”表示已加入响应，不表示模型已阅读；结果不明时不自动重发原工具。

## 左侧项目与对话

“对话”标签只保留在项目标题右侧，删除每个对话前的重复标签及右侧独立管理按钮。右键菜单提供明确的“打开”，右键本身不切换中央页面；项目菜单可打开真实项目目录。

单个项目默认显示近 72 小时最多 5 条对话，依次展开到 15 条和全部现有记录的虚拟化分页。近期不足五条不使用旧记录凑数，只有历史记录也保留展开入口。收起后重新打开恢复默认级别。搜索可访问历史内容，项目之间独立分页，不受最前面 200 条全局记录截断。

状态及时更新，自动排序最多每 60 秒评估一次；相邻项目或对话的真实活动时间差小于 60 秒时维持原有顺序。列表按稳定 ID 修改，不再周期性清空重建，并保留选中项、滚动位置和右键目标。

## 提示与深色主题

历史保留期限提示使用固定类型保存关闭状态。关闭后跨对话、重连和重启不再重复显示，其他连接、权限和保存错误独立处理。偏好升级到 schema 3，保留旧设置和未知扩展字段，遇到损坏或较新格式时不覆盖原文件。

插件卡片、展开后的 Skill/MCP 行、诊断文字和边框使用共享动态主题资源。删除固定白色背景和固定颜色，主题切换不需要刷新列表或重启 Core。MCP 工具数量未发现时不显示成确定的零。

## 任务成功通知

应用/托盘独立观察任务成功完成，在右下角显示一次性提示，点击定位具体任务及来源分支，不跳到该对话后来启动的另一个任务。单条工具、步骤、分支结束和任务取消不触发成功提示，左侧不添加完成标签。

完成身份与任务成功状态同时持久化，辅助活动日志写入失败不会丢失完成身份。多个观察窗口共享领取状态，刷新、重连和进程重开不重复通知。旧版本历史完成记录不补弹；弹窗约八秒后关闭，悬停暂缓关闭，不抢焦点。

## 托管 MCP 覆盖与运行时更新

mcp_manage 增加 update 与 reset_override，使用 inspect 返回的 revision 做并发比较。scope=runtime 仅本次进程有效，scope=persistent 保存在宿主覆盖文件中；优先级为运行时覆盖、持久覆盖、插件默认。插件标准包不被改写，归属、启用状态、凭据和权限仍由原有管理入口负责。

简介和元数据更新保留现有连接和排队/在途调用。连接目标变化先验证候选配置，再原子切换并等待旧代调用结束；失败保留上次可用连接与工具目录。版本来自 initialize 的真实 serverInfo，数量来自实际工具目录；不能用覆盖文本伪造发现事实。

上下文、plugin_load、搜索、inspect 和桌面模型共享能力修订。已使用的能力变化时，在后续工具响应中附加一次简短提示，要求重新读取有关工具，不展开无关 Heavy 插件。不保证强制刷新外部宿主已经缓存的旧对话内容。

## 自动化验证与交付范围

新增回归覆盖 120/180/300 秒边界、旧调用不领取、迟返回、跨对话与任务切换、重复发送、并发领取、进程重启、损坏队列保存、任务级通知持久去重、MCP CAS/覆盖优先级/失败刷新/排队锁竞争，以及项目分级展示和主题/布局契约。

Windows Package 工作流增加 installation_tests 开关。此次手动构建设置 false，安装器契约走 StaticOnly 分支，离线 Setup 安装/卸载步骤跳过。构建产物附带 verification-scope.json，分别记录已执行的自动化检查与未执行的安装、人工界面测试。
