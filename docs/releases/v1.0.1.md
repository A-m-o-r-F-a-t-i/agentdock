# AgentDock 1.0.1 — 标准化插件、AGENTS.md 上下文与 Windows 稳定性修复

　　1.0.1 汇总本分支相对上游主线新增的 Agent 标准目录、标准插件与 Heavy 渐进加载、能力与运行配置管理面板、AGENTS.md 自动上下文，并修复真实 Windows 覆盖安装中的启动失败、回滚状态失真、PowerShell 黑窗、Tunnel 停止竞态及功能与插件页加载问题。本发行版发布 Windows x64 离线安装包及便携运行时 ZIP。1.0.0 保留原附件与故障说明，撤下推荐状态，不静默替换已发布文件。

## 相对上游主线的核心新增能力

- **Agent 标准目录与可移植配置**：当前激活 Skill 使用与 Codex 对齐的可见目录树，插件采用 Agent Plugins 1.0.0、Agent Skills 与 MCP 标准清单。符合这些规范的 Skill、MCP 与插件内容可以直接放入标准目录或包中复用，无需先转换为 AgentDock 私有格式；版本状态、本机开关、凭据引用和持久数据继续由宿主独立管理。
- **标准插件与 Heavy 扩展**：插件目录直接包含 `plugin.json`、`mcp.json`、`skills/` 及实现资源，不增加插件 cache 中间层。AgentDock 仅在标准 `extensions.io.github.uvwt.agentdock.heavy` 命名空间增加 Heavy 参数；普通插件直接暴露启用成员，Heavy 插件第一层只暴露插件摘要，调用 `plugin_load` 后第二层才展开 Skill/MCP 描述与工具索引，适合封装大型专业能力而不持续占用上下文。
- **插件、Skill 与运行参数管理面板**：“功能与插件”页集中管理插件、Skill、MCP 的收起/展开、启停、成员开关和 Heavy 状态，避免同一成员在顶层重复展示；新增“运行配置”页管理默认全局工作区、AGENTS.md 自动加载、额外指令文件、浏览器程序、可信代理范围、命令环境变量引用以及 ACP 并发与交互超时等原本需要修改配置文件的参数。
- **AGENTS.md 自动上下文**：Core 自动加载用户目录 `AGENTS.md` 以及当前工作区路径上的项目 `AGENTS.md`，并按全局到项目顺序注入上下文。`agentdock_context(workdir)` 可以按请求切换工作区并重新读取最新规则，不改变命令默认目录，也不要求客户端单独发现和拼接规则文件。

## 安装与恢复

- 安装器外层命令通过 GUI 子系统原生执行器启动，使用 `CREATE_NO_WINDOW`。需要独立存活的 Core/Tray 通过原生 Task Scheduler COM 在当前用户会话中启动，临时任务不再运行交互式 PowerShell。有限命令、后台进程和安装器各自有明确的退出、超时及清理责任。
- 以随机事务 ID 关联请求与完成回执，保留 UTF-8 输出、实际子进程退出码和诊断。旧回执不能掩盖本次失败，安装器在 Engine 返回 JSON 前失败也能识别并恢复自己的事务。
- 修复进程被终止后新旧 Core 都被插件库锁阻塞的问题。确定所有者进程已经退出的锁可立即恢复，Windows 锁探测不再阻止合法删除，并保留同进程并发互斥。
- 新版本只有在健康检查确认目标版本后才完成提交。回滚先恢复 generation 文件、凭据与运行配置，再恢复旧 Core，并在确认旧版本健康后写入 `rolled_back`。失败时保留恢复资料，不报告已经完成回滚。
- 首次安装在激活前保留事务恢复资料，最终成功时刷新健康结果。覆盖安装和同版本修复使用同一恢复闭环。支持含中文及空格的安装目录。
- 安装目录、地址与 Token 校验支持 Inno 的静默错误抑制，避免无人值守安装被校验弹窗卡住。安装日志随实际安装目录保存。

## Tunnel 生命周期

- 停止信号传递到 URL 生成、cloudflared 等待和 Core 配置重载阶段，停止命令可取消尚未完成的启动。
- 按 runtime root 串行化生命周期操作，并修复 Windows 内核互斥量的 OS 线程归属。重复启动识别真实活动 generation，不重复创建 supervisor。
- Core 重载被停止信号中断时仍启动有界恢复流程，避免本地 Core 留在离线状态。记录 supervisor PID、cloudflared PID、运行阶段和退出耗时。

## 功能与插件

- Skill 清单每轮使用一次插件成员快照，移除逐项重复扫描。新增轻量摘要接口，完整文件列表及文件数量仍保留在原接口中。
- 控制面板并行加载插件、Skill 和 MCP 清单，先呈现已取得的数据。慢 MCP 或 Nexus 状态查询不阻塞本地插件卡片，单一栏目失败会明确显示错误并保留其他栏目和上次数据。
- Heavy 插件收起时不创建成员控件，展开时才构建详情。增加有大小限制的分阶段耗时日志。
- 修复 Skill/插件管理 POST 请求正文丢失，以及 Heavy 开关动作未加入允许列表的问题。

## 验证范围

　　实机环境为 Windows x64 标准用户会话，测试使用独立 AppID、端口、启动项、用户目录及含中文和空格的路径。测试不覆盖真实生产实例。原生启动器额外覆盖 Windows PowerShell 5.1 的 32 位和 64 位进程、嵌套启动、后台进程存活、错误退出及超时清理。

| 验证项 | 验收规则 |
| --- | --- |
| 0.8.3 与 0.8.4 插件版升级 | 使用真实 Inno EXE 升级后，Core 版本为 1.0.1，事务 committed 且 healthy=true |
| Core 启动失败、提交前失败 | 自动恢复旧版本 HTTP 健康，事务 rolled_back 且 healthy=true，凭据与用户数据保持不变 |
| 同版本修复与回滚 | 修复后健康；失败时恢复原 generation 文件哈希 |
| 首次安装与卸载 | 首次启动健康；未授权删除用户数据时保留用户目录 |
| 黑窗检查 | 经过正对照校准的 WinEvent 显示事件与 20 毫秒轮询未记录到新控制台窗口；子进程控制台句柄为零 |
| Tunnel | 真实 cloudflared 重复启动、重建、停止，以及阻塞和 Core 重载期间取消均保持可恢复状态 |
| 插件页 | 慢服务、HTTP 错误、异常 JSON、取消和收起/展开行为分别测试；实际 HTTP 开关请求通过 |
| 源码 | `go test -p 4 ./...`、`go vet ./...`，控制面板构建和 WPF 回归 |

　　同一生产数据副本包含 3 个插件、15 个 Skill 和 3 个 MCP。每种接口测量 5 次，旧 Core 的完整 Skill 清单耗时 1097–2625 毫秒，修改后的完整清单为 86–89 毫秒，摘要为 76–86 毫秒。该范围来自本次主机与数据副本，不代表所有磁盘、插件规模或设备上的固定耗时。

　　安装与窗口回归针对 Windows x64 标准用户场景。Windows ARM64、其他 Windows 用户配置及非 Windows 桌面安装器不在本次实机验收范围内。本次回归不通过放宽系统权限或关闭 Inno 文件系统保护来规避失败。
