## 3. 对象关系与执行绑定

　　Conversation 表示一次可识别的宿主对话。Task 保存长期目标、步骤和生命周期，可以跨 Conversation 接续。Call 表示一次实际工具调用，并携带进入执行器时冻结的 Conversation、可选 Task、TaskThread 和 Workspace。Command Session 保存长命令进程及其输出，持续使用创建时的 Call 绑定。Activity Event 保存开始、输出、审批和完成等事件，由 Call 投影形成界面记录。

　　接入层创建不可变 ExecutionScope 并写入 `context.Context`。内部子调用继承来源和任务快照，生成新的 CallID 和 ParentCallID。审批绑定具体 CallID 与固定请求，不能通过批准请求替换命令或动态 MCP 目标。重复批准不会重复派发。

　　任务创建、恢复、设为当前任务和任务分支切换更新 ConversationState。查看另一任务及切换列表选择不修改默认执行绑定。任务完成、取消或解绑后，新调用不继续继承旧 Task。已运行和待审批的 Call 保留旧快照，不随之后的选择变化。

　　对话视图和任务视图读取同一份 Call 投影。无 Task 时仍展示执行卡片，只省略任务进度卡。任务 checkpoint 使用独立里程碑样式，内部转发和子调用通过展开查看。

## 5. 宿主元数据验证与降级

　　当前依赖为 MCP Go SDK `v1.7.0`。已检查实际 SDK 类型并编译运行真实 SDK／HTTP 测试，接入读取路径为 `request.Params.Meta["openai/session"]`，对应协议请求中的 `_meta["openai/session"]`。测试客户端在请求元数据中提供宿主标识，业务参数没有 `conversation_id`。

　　`TestExecutionSDKMetadataTwentyCallsAndReconnect`、`TestExecutionTwentyConcurrentCallsPerConversation` 等测试覆盖每个对话 20 次调用、并行同工作区隔离及重连后的同宿主映射。原生候选 Core 也通过了元数据和任务／线程继承测试。外部标识按提供方、认证主体范围、接入来源及宿主标识映射为本地 `conv_...`，不直接作为界面显示值或主键。

　　实际 ChatGPT 网页连接是否透传该字段尚未取得可核验结果。这些测试使用真实 SDK 和 HTTP 传输，但宿主元数据由测试客户端注入，不能据此将实际网页连接验收标为通过。

　　元数据缺失时，普通 MCP 接入保留空 ConversationID，`binding_quality=unattributed`，进入“来源未识别”导航分组。不会生成 `conv_unknown` 或全局假对话，不按相邻请求、工作区和 UI 选择推测来源。无法建立可靠对话绑定时，返回绑定警告，不要求模型补 ConversationID。

　　仅接入层已经确认连接与对话一一对应时，才允许 `connection_fallback`。普通 `Mcp-Session-Id` 不自动满足该条件。无法可靠识别来源时，后续任务自动继承也不能假定成立；调用仍完整留存，TaskID 可以为空。
